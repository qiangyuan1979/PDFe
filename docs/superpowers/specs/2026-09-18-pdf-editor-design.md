# PDF 编辑器 设计文档

- 日期：2026-09-18
- 状态：待用户最终审阅
- 项目代号：PDFe

## 1. 概述

### 1.1 产品定位

面向公众的 Windows 桌面 PDF 编辑器，免费发布并保留商业化可能，目标是上架 Microsoft Store（MSIX 包）。界面追求美观与易用性，功能覆盖阅读、页面管理、合并拆分、水印（添加与去除）、深度内容编辑。

### 1.2 目标用户

普通 Windows 用户：学生、办公人员、自由职业者。他们需要一个本地、快速、界面现代的 PDF 工具，而不是臃肿的企业套件或充满广告的在线工具。

### 1.3 开发方式

AI 主导开发，产品所有者以产品视角决策。技术选型需考虑长期可维护性。

## 2. 需求范围

### 2.1 v1 功能清单（MVP）

| 模块 | 功能点 |
|------|--------|
| 阅读 | 连续滚动/单页/双页对开；Ctrl+滚轮缩放、适应宽度/窗口；缩略图与书签导航；全文搜索（结果列表、高亮遍历 F3/Shift+F3）；记住上次阅读位置与缩放 |
| 页面管理 | 多选（Ctrl/Shift）、拖拽重排；右键菜单：旋转/删除/复制/提取/插入空白页 |
| 合并 | 多文件合并向导：拖入排序、每文件可选页码范围、合并预览 |
| 拆分 | 四种模式：每 N 页一档、自定义范围、按书签顶层、提取选中页；输出多文件自动命名 |
| 水印添加 | 文字/图片；字体/字号/颜色/透明度/旋转；位置：九宫格/平铺/拖放自定义；范围：全部/当前/自选；当前页实时预览 |
| 水印去除 | 自动检测（内容流分析找每页重复对象 → 候选清单 → 勾选 → 预览 → 移除）+ 手动框选擦除（兜底） |
| 深度内容编辑 | 双击文字进入编辑态；保存时「遮盖原区域 + 原字体样式重绘」；T 工具新增文本框；图片选中/移动/缩放/替换/删除 |
| 安全 | 设置打开密码与权限密码；移除密码（需持有密码） |
| 导出 | 页面导出为 PNG/JPG |

### 2.2 非目标（v1 明确不做）

- OCR 识别扫描版文字（v2 候选）
- PDF 转 Word/其他格式
- PDF 压缩优化
- 跨平台（macOS/Linux）与移动端
- 协作、云同步

### 2.3 诚实边界

扫描版（纯图片）PDF 无法编辑文字：v1 检测后明确提示「此文档为扫描版，暂不支持文字编辑」，不静默失败。OCR 列入 v2 路线。

## 3. 技术选型

### 3.1 决策

**Tauri 2 + React + TypeScript（前端）+ Rust（后端）+ PDFium（PDF 引擎）**

### 3.2 备选方案与弃选理由

| 方案 | 弃选理由 |
|------|----------|
| Electron + React | 安装包 ~120MB、内存占用高，商店体验差；其余能力与 Tauri 方案等价 |
| .NET 8 + WinUI 3 | 商店路径顺但 UI 现代感与开发效率不及 Web 技术 |
| Python + PySide6 | 打包 MSIX 上架路径痛苦；且强依赖的 PyMuPDF 为 AGPL 授权 |

### 3.3 授权审计（商业化安全）

| 依赖 | 授权 |
|------|------|
| PDFium（pdfium.dll） | BSD-3-Clause / Apache-2.0 |
| pdfium-render（Rust 绑定） | Apache-2.0 / MIT |
| Tauri | MIT / Apache-2.0 |
| React / Zustand 等 | MIT |

红线：不引入 AGPL 依赖（PyMuPDF、iText、MuPDF 均禁用）。

## 4. 系统架构

### 4.1 进程模型

双进程：WebView 前端进程（React + TypeScript）负责界面；Rust 核心进程负责所有 PDF 操作。两者通过 Tauri IPC 通信（JSON 参数、二进制返回 ArrayBuffer），事件流用于进度推送与文档变更通知。

### 4.2 Rust 核心模块

| 模块 | 职责 |
|------|------|
| 渲染模块 | 页面按缩放比渲染为位图（DPI 感知）、缩略图生成 |
| 页面管理模块 | 合并/拆分/重排/旋转/删除/插入 |
| 水印模块 | 添加（文字/图片页面对象、平铺）、去除（内容流分析 + redaction 删除） |
| 编辑模块 | 文字改写（检索→遮盖→重写）、图片操作、新增文本框 |
| 搜索模块 | 全文检索、定位与高亮坐标 |
| 文档模块 | 打开/保存/另存、元数据、加密解密、撤销快照 |

所有 PDF 能力统一由 PDFium 提供：渲染、页面对象创建与修改、文本提取与检索、redaction（内容删除）机制。低层 API 若 pdfium-render 未封装，直接使用其原始绑定。

### 4.3 前端结构

- 布局：工具条 + 三栏工作台 + 状态栏（React 组件）
- 画布：Canvas 渲染组件，消费 Rust 返回的位图
- 状态管理：Zustand
- 撤销/重做：UI 层栈与 Rust 快照栈联动
- 位图缓存：LRU（防大文档内存膨胀）

### 4.4 关键数据流

1. 打开：选文件 → Rust 加载 → 返回句柄 + 页数/元数据 → 前端建缩略图队列
2. 渲染：可视区需要第 N 页 → Rust 按缩放比渲染 → ArrayBuffer 回传 → Canvas 绘制 + LRU 缓存
3. 编辑：任务面板提交参数 → Rust 修改文档 → 返回变更页集合 → 前端仅重渲染受影响页（增量刷新）
4. 保存：完整保存或增量保存

### 4.5 撤销/重做

Rust 侧文档快照栈（内存序列化快照），双重上限：条数 20 步、单文档内存 256 MiB；超出即从栈底（最旧）淘汰，至少保留 1 条。每次结构化操作（页面/水印/编辑）前压栈。

### 4.6 性能策略

- 只渲染可视区页面；预渲染相邻页
- 渲染在后台线程执行，UI 不阻塞
- 增量刷新：编辑只重渲染受影响页

## 5. UI/UX 设计

### 5.1 主窗口布局（混合方案：三栏工作台 + 经典工具条）

```
┌────────────────────────────────────────────────┐
│ 顶部工具条：Logo | 合并 拆分 水印 编辑 旋转 删除页 | 搜索框 │
├────┬──────────┬──────────────────┬─────────────┤
│活动 │ 页面缩略图  │                  │ 右侧任务面板    │
│栏  │ /书签 Tab │    中央画布        │ (按需展开      │
│    │          │  (编辑态浮出工具胶囊) │  完成自动折叠)  │
├────┴──────────┴──────────────────┴─────────────┤
│ 状态栏：文件名 · 页数 · 大小 | 保存状态 · 缩放控制     │
└────────────────────────────────────────────────┘
```

### 5.2 交互模式

- 顶部工具条：常用操作一步直达，新用户零学习成本
- 左侧：活动栏（阅读/页面/批注/水印/任务/设置）+ 双 Tab 面板（缩略图 | 书签）
- 缩略图栏：多选、拖拽重排（插入位置指示线）、右键菜单
- 右侧面板：点击工具时展开，操作完成或取消后自动折叠
- 画布浮动胶囊：进入编辑态时出现（选择/编辑/文字工具），退出即隐藏
- 主题：跟随 Windows 系统深浅色自动切换

## 6. 错误处理

- 所有 Rust 操作返回统一错误类型 → 映射为用户友好的中文 toast
- 加密 PDF：打开时识别，弹密码输入框；密码错误可重试
- 损坏文件：明确报错，不崩溃
- 保存安全：原子写入（先写临时文件，成功后替换原文件）；失败时原文件保持不动并提示
- 大文件：后台线程处理；超过内存阈值时给出提示
- 扫描版 PDF：编辑入口给出明确提示（见 2.3）

## 7. 测试策略

- Rust 单元测试：黄金文件测试（样例 PDF → 操作 → 断言输出结构/文本），覆盖六大模块
- 前端：Vitest + Testing Library 组件测试
- E2E：tauri-driver + WebDriver 跑核心流程（打开 → 编辑 → 保存）
  - 实际落点：`src-tauri/tests/commands.rs` 用 `tauri::test` mock 运行时直调真实 `#[tauri::command]`，
    覆盖同一链路（打开 → 编辑 → 保存 → 撤销/重做 → 关闭）。未采用 tauri-driver：其依赖
    WebView2 真实驱动与独立 exe 启动，本机与 CI 均不稳定
- 手工回归清单：多语言 PDF（中日韩、RTL）、扫描版、加密文档、超大文件（500+ 页）

## 8. 打包与上架

- `tauri build` 产出 Windows 可执行文件与安装包
- 使用 makeappx 打包 MSIX + signtool 签名
- 提交 Microsoft Store：需要开发者账号（个人版一次性费用约 $19）
- 应用更新走 Store 自带机制，不自建更新器
- 崩溃诊断：v1 保留本地日志文件，不接第三方收集服务

## 9. 版本路线

- **v1（本设计）**：阅读、页面管理、合并拆分、水印、深度编辑（遮盖-重写）、密码、导出图片；上架 Store
- **v2 候选**：
  - **原生阅读非 PDF 文档**（新增）：markdown / HTML / 纯文本与源码（.txt .cpp .php .js 等）/ EPUB，在应用内直接打开阅读，不做转换
    - 编码检测：自动判别 UTF-8 与 GB18030，避免中文 txt、源码乱码
    - HTML 必须沙箱渲染（不执行文档内脚本），防止打开即执行任意代码
    - 边界：MOBI / AZW3 格式规范未公开，无可靠原生解析方案，仍走既有的 Calibre 转换 → PDF 路径
  - OCR（扫描版可编辑）
  - PDF 压缩
  - 格式转换（Word/图片转 PDF）
  - 页面模板
  - 批量处理队列
- **远期**：跨平台（Tauri 天然支持，届时补 macOS 公证与 Store 流程）

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| PDFium 部分低层 API 无高级封装 | pdfium-render 暴露完整原始绑定，必要时直接调 C API |
| 深度编辑的字体还原不完美 | 检测到近似替换时在 UI 明确提示，不假装完美 |
| 水印自动检测误删正文 | 强制预览确认步骤 + 撤销快照兜底 |
| 非专业开发者维护 Rust 代码 | 模块边界清晰、单测覆盖、AI 辅助维护 |
